## Wave 4 findings (what Wave 5 builds on)

### Root cause fully traced

WPT math-function tests (CSS Values 4 §10) require THREE coordinated fixes that ALL must land together or none at all:

| # | Location | Fix | Subtest impact alone |
|---|----------|-----|----------------------|
| 1 | `src/js/kotori/vm.zig:1308` (get_elem), `:1398` (set_elem) | DOM node/style bracket-access dispatch | **−740 css/css-values** (net-negative without #2/#3) |
| 2 | `src/css/parser.zig` + `properties.zig` + `values.zig` | Math function token acceptance: min/max/clamp/round/mod/rem/abs/sign/trig/pow/sqrt/exp/log/hypot | 0 alone (not reachable via WPT without #1) |
| 3 | `src/css/cascade.zig` + `src/js/dom_style.zig::resolveInlineForComputed` | Math function computed-value resolution + serialization | 0 alone (not exercised without #1/#2) |

### Net-negative when shipped alone

- Fix #1 alone reverted: enables the bracket path, but values flow to `dom_set_prop` → css parser rejects math tokens → err state. 75 more test files err-out. Net: -740 css/css-values, +52 dom/nodes, +10 css/cssom = **-678 net**.
- Fix #2 alone: parser accepts math tokens but tests never reach parser (bracket path broken). 0 delta.
- Fix #3 alone: resolve/serialize work at cascade level but WPT tests use inline path. 0 delta.

**Critical invariant**: all three must be atomic in a single commit (or sequence of pre-tested commits) to avoid Wave 4-class regression.
