## Task 11 retry preconditions (from third-drop §Follow-ups)

Before any future Layer 1D.2 / Task 11 polyfill-deletion attempt:

1. **Property-descriptor hygiene task**: audit and fix Element.prototype own-property leakage. `Object.getOwnPropertyNames(elem)` must return only WebIDL-spec-defined names, not internal slots. Requires `[LegacyUnenumerableNamedProperties]` analogue in `kotori_dom.zig` wrapper generation.
2. **Return-value correctness task**: unit tests (not just WPT) for `removeAttributeNode` returning the removed Attr, `getAttributeNames` returning the array — must pass before any polyfill-deletion retry.
3. **Runtime behavioral diff tool**: new tool that runs a fixture set with and without `attributes_polyfill_js` loaded, compares observable JS-level behavior (own properties, prototype chain, method return values), and emits a diff report. This is the non-negotiable prerequisite per Wave 2 L2.

All three must pre-land before Layer 1D.2 can be scoped.

## Suggested Wave 3 shape

Two reasonable shapes:

### Shape A — Single big design wave

Open with spec authoring for Layer 3B (Priority 1). Ship Layer 3B implementation across Wave 3. Defer everything else. Pro: measurable coverage gain. Con: single-layer risk if 3B turns out harder than estimated.

### Shape B — Cluster + retry preconditions

Open with Layer 1F (Priority 3, design already authored) + the three Task 11 preconditions (runtime diff tool, property hygiene audit, return-value unit tests). Close with measured Δ and a ready-to-land Layer 1D.2. Pro: unblocks two waves of work. Con: smaller single-wave coverage gain.

Recommended: **Shape B** if Wave 3 planner has bandwidth; **Shape A** only if 3B spec can be authored in ≤ 1 day and has no blocking dependency on the runtime diff tool.

## Anti-patterns to avoid (lessons from Wave 2 iterations 1-2)

- Do NOT plan against the master roadmap doc without a live State Survey.
- Do NOT assume a layer is unmerged because its feature branch still exists — branches can be 0-commits-ahead of main if merged via fast-forward.
- Do NOT scope "polyfill deletion" as a single task. It's a multi-step migration requiring runtime equivalence demonstration first.
- Do NOT treat post-mortem as gate if it's structural only. Functional-equivalence evidence required (Wave 2 L2).
